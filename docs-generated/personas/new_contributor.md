# New Contributor

## Who Is This Persona

**Persona:**
new contributor

**Description:**
Learning the repository for the first time.

**Goals:**
['Understand project', 'Navigate codebase', 'Learn workflows']

**Workflow:**
['brain project analyze', 'brain project summary', 'brain diff explain']

**Commands:**
['brain diff explain']

## Typical Responsibilities

*   Acquiring foundational knowledge of the project's architecture and design patterns.
*   Identifying key entry points and core functional modules within the codebase.
*   Familiarizing oneself with existing coding standards, documentation, and pull request processes.
*   Assimilating into the development lifecycle by observing how changes are implemented and reviewed.

## Recommended Approach

1.  **Analyze the Landscape:** Use `brain project analyze` to generate a high-level overview of the repository structure and identify technical debt or complex modules.
2.  **Synthesize Knowledge:** Execute `brain project summary` to extract documentation and architectural intent, helping to bridge the gap between abstract requirements and concrete implementation.
3.  **Learn by Example:** Utilize `brain diff explain` on recent merged pull requests to understand how code changes are proposed, justified, and integrated by experienced maintainers.
4.  **Iterative Exploration:** Focus on small, isolated components before attempting to modify core logic to minimize risk and maximize learning velocity.

## Common Scenarios

*   **Onboarding:** You have just cloned the repository and need to identify where the core logic resides without manually parsing every file.
*   **Feature Contribution:** You need to implement a new feature and are looking for existing patterns that match your requirements to ensure consistency.
*   **Debugging:** You encounter a bug in an unfamiliar part of the codebase and need a clear explanation of how the data flows through that specific module.
*   **Code Review Participation:** You are tasked with reviewing another contributor's PR and need to understand the intent behind the diff to provide meaningful feedback.
