## Usage Guide

### When would I use this?

Use `brain diff review` when you need an automated, concise explanation of code changes between commits, branches, or your working directory. It is ideal for peer reviews, summarizing complex features, or understanding the impact of changes made by others without manually inspecting every line.

### How it fits in the workflow

1. **Local Development**: Run `brain diff review` before committing to generate a commit message summary.
2. **Pull Request Preparation**: Use it to generate a description for a PR body so reviewers understand the intent behind the code changes immediately.
3. **Code Auditing**: Integrate it into your git hooks or CI pipeline to flag logic shifts or potential regressions in incoming feature branches.

### Practical tips

* **Target Specific Ranges**: Use syntax like `brain diff review HEAD~1 HEAD` to isolate changes to the most recent commit.
* **Context Matters**: Ensure your branch is up to date with the remote before running the command to ensure the LLM reviews the intended logic against the latest codebase.
* **Large Diffs**: If the diff is extensive, the LLM may take longer to process; consider staging smaller, atomic commits for more accurate and faster results.

### Common failure causes

* **INVALID_GIT_REF**: The provided commit hash or branch name is malformed or does not exist in the local repository. Verify your references using `git log`.
* **LLM_PROVIDER_FAILURE**: The configured AI service (e.g., OpenAI, Anthropic) is unreachable, the API key is expired, or the service has hit a rate limit. Check your network configuration and provider billing status.

### FAQ

**Does this modify my code?**
No, `brain diff review` is a read-only operation. It only analyzes the differences between code versions and provides an explanation.

**Can I customize the output format?**
The output is generated by your configured LLM provider. You can influence the style by adjusting your global prompt settings if the tool provides a configuration file.

**What happens if I don't provide a git ref?**
The tool defaults to comparing your current working directory against the last commit (`HEAD`).
