# New Contributor

## Who Is This Persona

**Persona:** New Contributor
**Description:** Learning the repository for the first time.
**Goals:** ['Understand project', 'Navigate codebase', 'Learn workflows']
**Workflow:** ['brain project analyze', 'brain project summary', 'brain diff explain']
**Commands:** ['brain diff explain']

## Typical Responsibilities

*   Acquiring foundational knowledge of the project architecture and domain.
*   Identifying key entry points and core logic within the codebase.
*   Adapting to existing development lifecycles, branching strategies, and testing requirements.
*   Submitting small, low-risk patches to gain familiarity with the CI/CD pipeline.
*   Asking clarifying questions based on technical documentation and existing pull requests.

## Recommended Approach

1.  **Contextual Mapping:** Execute `brain project analyze` to generate a high-level overview of the architectural components and module dependencies.
2.  **Summarization:** Use `brain project summary` to extract the core mission and functional purpose of the repository.
3.  **Iterative Learning:** Select recent, completed pull requests and utilize `brain diff explain` to understand the reasoning behind specific implementation changes.
4.  **Hands-on Exploration:** Review the documentation alongside code exploration to connect theoretical design with practical implementation.
5.  **Incremental Engagement:** Begin by reviewing existing code before attempting to contribute documentation fixes or minor bug resolutions.

## Common Scenarios

*   **Onboarding:** Utilizing `brain project summary` to get up to speed during the first week of repository access.
*   **Code Reviewing:** Applying `brain diff explain` on peer-submitted pull requests to learn the expected coding standards and style.
*   **Debugging Assistance:** Running `brain project analyze` when stuck on how a specific feature interacts with the rest of the system.
*   **Task Resolution:** Using the established workflow to ensure that the logic behind a proposed contribution aligns with the project’s overarching design goals.
