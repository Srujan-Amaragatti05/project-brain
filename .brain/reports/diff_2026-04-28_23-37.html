The system dependency on Git logic has been abstracted away to sub-modules, changing the execution flow from a direct action to a router-style command.

Change

The implementation transitioned from a raw subprocess invocation to a wrapper function run_git_command, while also introducing a new 'root' variable reference. By abstracting the git command execution, the function signature relies on an external context variable that was previously absent, and it shifts the error handling mechanism from explicit exception catching to a null-check pattern.

Impact

This change standardizes git interaction across the codebase, potentially reducing boilerplate and ensuring consistent environment configurations. However, it introduces an implicit dependency on the 'root' variable scope, which could lead to NameErrors if the variable is not defined in the caller's scope, deviating from the previous self-contained logic.
